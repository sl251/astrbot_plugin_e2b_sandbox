## 已修复的问题与验收条件

| 风险 | 原行为与影响 | 本版修改 / 后续验收 |
| --- | --- | --- |
| P1：状态文件损坏 | 解析失败或顶层非对象被当作空记录；新请求可能遗忘已有实例与占用名额。单条非对象又会在初始化时崩溃。 | 校验记录和有限、非负时间值，失败停止加载，保留原文件。覆盖非法 JSON、数组、空记录、错误字段类型、NaN/Infinity；核实没有覆盖原文件或发出 RPC。合法的旧版本记录仍应加载。 |
| P1：激活前持久化失败 | 写盘失败仅打日志，CREATE/CONNECT 仍执行；重启后可能找不到新实例，或把已恢复实例当作暂停。 | 新建、重连前严格保存意图，flush/fsync 后原子替换；失败回滚内存，暂停实例释放预留名额，运行实例保留名额。分别注入打开、写入、fsync、替换失败，确认无激活及补偿暂停 RPC。旧 Key 迁移失败应停止加载。 |
| P1：卸载遗漏执行中的会话 | 卸载跳过持锁会话，可在其继续执行时返回；新实例可能读取过时记录。 | 从停止入口拒绝新操作，等待会话作用域完成，再收尾。覆盖创建、恢复、执行、auto_pause=false、取消和面板动作并发卸载；确保等待的是操作范围，而非宿主整条消息任务。 |
| P2：暂停计时残留 | 云端手动恢复后查询到 running，却保留旧 paused_at；下一次查询到 paused 时可能立刻触发到期销毁。 | running/未知云端状态移除旧 paused_at；未知状态占用名额。验证 paused → 云端 running → 查询 → 云端 paused → 查询，新的暂停保留期从本次确认起算。 |
| P2：代码去重误拦截 | 上传/安装失败也写代码指纹；销毁后马上重跑同一段代码被拦截。 | 指纹移到代码调用前；确认删除记录时清指纹。覆盖准备阶段重试、执行超时仍去重、销毁后立即重跑、404 清记录。 |
| P2：界面与后端不一致 | 重复 ID 的操作按钮可点但后端拒绝；配置 100 MB 时面板显示 100，实际执行器上限 50；缓存附件被称作待传；冷却到期仍显示不可用。 | 快照与动作共同拒绝重复目标；上限共享常量；显示缓存附件、可轮询与待刷新。覆盖筛选、分页、倒计时、自动刷新关闭、操作后刷新失败。 |
| P2：Key 输入与日志 | 列表中的 null、数字被转换为凭据；短 Key 先替换可能留下长 Key 后缀。 | 只接收非空字符串，按长度降序脱敏。覆盖混合类型、空白、重复 Key、包含关系和列表重排。 |
| P2：旧会话创建时间错误 | 旧记录没有 created_at，重连时却标记为“刚创建”。 | 对已有记录保留未知时间，面板显示「—」；新建沙箱仍记录创建时间，恢复不重置。 |

## 测试模型接手建议

1. 在隔离环境补齐上表回归用例，再运行 `python -m unittest discover -s tests -v`。现有 CI 为 Python 3.10/3.12 × minimum/current SDK；minimum 为 e2b-code-interpreter 2.3.0 与 e2b 2.6.0，current 按 requirements.txt 安装。
2. 真实 AstrBot 中核对 `register_web_api`、`astrbot.api.web.request`、宿主 JWT 以及页面桥接契约。现有面板测试使用宿主替身，不能证明某个已安装 AstrBot 版本的端到端兼容性。旧宿主应安全显示不可用。
3. 在支持面板的宿主验收登录/退出、iframe 来源、暂停/销毁二次确认、过期目标拒绝、页面关闭后操作收尾、深浅主题与窄屏显示。
4. 用真实多账户验收新建轮询、原 Key 恢复、Key 缺失、额度/限流、重载迁移；超时和 5xx 不能跨账户再建。真实云端验收会产生资源消耗，使用测试账户并及时清理。

## 保留的限制与后续改进

- 快照仍是本地追踪，不主动查询云端；云端外部操作和停机期间的变化需要后续状态查询/维护确认。未来可考虑有并发上限的只读云端核对入口，不应通过 CONNECT 刷新列表。
- 持久化只适合一个插件实例写入同一个状态目录；fsync 与原子替换不提供跨进程锁，也不保证所有文件系统的断电目录持久性。多进程共享目录需独立设计锁或事务存储。
- 状态文件确实丢失时仍会被视为首次安装，无法凭空恢复未知账户和云端实例；应保留状态备份。
- 卸载会等待进行中的操作。底层 SDK 或平台文件接口若永久不返回，仍可能拖延卸载；统一操作预算与有界取消需要单独设计，避免取消后遗失仍可能运行的云端任务。
- 面板列表目前全量返回后在前端分页；大量会话下可进一步加入后端分页。Key 标签仍是当前配置顺序序号；可以增加不含密钥的用户自定义别名。

这些后续项未在 1.4.2 中宣称实现或通过测试。
