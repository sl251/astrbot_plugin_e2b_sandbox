# AstrBot E2B 云沙箱插件 (astrbot_plugin_e2b_sandbox)

![Platform](https://img.shields.io/badge/Platform-Windows%20%7C%20Linux%20%7C%20Docker-blue)
![License](https://img.shields.io/badge/License-AGPL--3.0-green)
![Python](https://img.shields.io/badge/Python-3.9+-blue)
![Status](https://img.shields.io/badge/Status-Active-brightgreen)

**使用 E2B 云沙箱安全执行 Python 代码，支持通过 LLM 自然语言调用。**

这是 AstrBot 的增强型代码执行工具，它将不安全的本地 Python 执行环境替换为隔离的云端沙箱。现在它不只是“能跑代码”，在文件处理、结果回传和自定义环境（Template）上已经有了一套非常顺滑的工作流。

## 💡 为什么用它？（核心优势）

- **💻 零服务器算力负担**：所有的代码计算、文件处理、画图都在 E2B 的云端服务器完成！**完全不占用你宿主机的 CPU 和内存**。哪怕你的 AstrBot 部署在 1核1G 的“乞丐版”小鸡上，照样能让大模型跑庞大的数据分析。
- **⚙️ 极简配置，开箱即用**：不用在宿主机折腾复杂的 Docker，也不用天天排查 Python 虚拟环境依赖冲突。装好插件，填个 API Key，立刻拥有完整的代码执行能力。
- **🛡️ 绝对安全隔离**：代码在云端执行，完全隔离于宿主机。再也不用怕模型发神经执行 `rm -rf /` 把你的服务器扬了。

## ⚠️ 重要前置要求（必读）

> [!IMPORTANT]
> 经实测，AstrBot 新版自带了“使用电脑能力”，请按以下说明配置以确保本插件完美运行：

### 🚫 不要开启全局 Sandbox
在 AstrBot 的管理面板中，进入 **“设置” -> “普通配置” -> “使用电脑能力”**，找到 **“运行环境”** 选项：
- 请将它设置为 `local` 或者 `none`。
- **千万不要设置为 `sandbox`**。
- **亲测：`local` 配合本 E2B 云沙箱插件可以顺利共存并完美运行**，功能不会冲突。

### 🌐 网络环境配置
E2B 服务端在海外。如果你的 AstrBot 部署在国内且网络不通，请在插件配置中填写 `proxy`（例：`http://127.0.0.1:10809`）。

## 🛠️ 安装与配置

### 1. 安装依赖
```bash
# 进入 AstrBot 的虚拟环境后执行
pip install 'e2b-code-interpreter>=2.3.0,<3.0.0'
```

### 2. 获取 E2B API Key
访问 [E2B Dashboard](https://e2b.dev/) 登录并复制你的 API Key。当前 Hobby 套餐无月费，新用户有 $100 一次性使用额度；运行中的沙箱按秒消耗额度，暂停的沙箱不计费，也不占运行并发名额。额度和限制以 [官方定价](https://e2b.dev/pricing) 为准。

### 3. 插件配置项

配置面板使用短标题显示设置名称，补充说明放在 AstrBot 的 `hint` 区域（不同版本显示为说明文字或问号提示）。如果更新后仍显示旧标题，请重新加载插件、刷新管理面板并重新打开配置窗口。升级不会更改现有配置键或默认值。

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `e2b_api_key` | 字符串 | 是 | 空 | E2B API Key |
| `timeout` | 整数 | 否 | 60 | 单次代码执行超时（秒） |
| `max_output_length` | 整数 | 否 | 2000 | 返回给 LLM 的最大文本长度 |
| `proxy` | 字符串 | 否 | 空 | E2B 请求代理地址 |
| `default_template` | 字符串 | 否 | 空 | 默认使用的 E2B Template ID |
| `enable_user_whitelist` | 布尔值 | 否 | true | 是否限制为白名单用户；关闭后所有用户可用 |
| `user_whitelist` | 字符串列表 | 否 | 空 | 允许使用的用户 ID；启用白名单时留空会禁止所有用户 |
| `max_running_sandboxes` | 整数 | 否 | 3 | 本插件实例中所有会话合计的运行/待确认沙箱上限（1–20） |
| `max_queue_size` | 整数 | 否 | 10 | 满员时最多等待的请求数（0–100）；0 表示直接返回繁忙 |
| `queue_wait_timeout` | 整数 | 否 | 15 | 排队等待名额的最长秒数（1–120） |
| `allow_keep_running` | 布尔值 | 否 | false | 开启后才允许模型使用 `auto_pause=false`；空闲暂停仍生效 |
| `idle_pause_seconds` | 整数 | 否 | 30 | 没有执行任务的运行沙箱空闲多久后暂停（5–3600 秒） |
| `paused_sandbox_retention_hours` | 整数 | 否 | 12 | 暂停沙箱保留多久后自动销毁（1–720 小时） |
| `max_upload_file_size_mb` | 整数 | 否 | 20 | 上传到沙箱的单个附件上限（1–100 MB），同时限制 URL 下载和本地附件读取 |
| `max_return_file_size_mb` | 整数 | 否 | 5 | 允许缓存/发送的单个结果文件大小上限（MB） |
| `file_retention_hours` | 整数 | 否 | 24 | `data/plugin_data/astrbot_plugin_e2b_sandbox/exports/` 缓存文件保留时长（小时） |

### 4. 开放给所有用户

关闭 `enable_user_whitelist` 即可。建议先保留默认的 3 个运行名额、10 个排队请求和 15 秒等待超时；容量限制与白名单开关独立，关闭白名单不会关闭容量保护。

**群聊共享边界**：插件优先以 AstrBot 的 `unified_msg_origin` 作为会话标识。适配器以群标识会话时，同一群里的用户共用一个沙箱、Python 变量、上传附件和导出文件缓存；有调用权限的成员可以读取、发送或覆盖其他成员的文件，也可以暂停或销毁整个群的沙箱。白名单控制调用权限，不提供群内成员之间的数据隔离。当前版本继续保留这一共享模式，适合群内协作，请勿把它当作个人私密工作区。

暂停的沙箱可以保留各自的文件和变量，需要执行时再排队恢复。因此用户总数可以大于运行名额。创建、恢复和代码执行都使用同一套容量管理，正在运行的沙箱不会重复占用名额。新建请求按至少 1 秒间隔发送，`429` 按服务端 `Retry-After` 做有限重试；创建结果不确定时不会盲目再创建一个沙箱。

容量限制作用于单个插件实例，不是 E2B 项目的分布式配额管理。多个 AstrBot 实例或其他程序共享同一个 E2B 项目时，也会共享服务端额度，仍可能收到 `429`。建议为此插件使用独立项目，并留出并发余量；持续使用仍会消耗运行额度。

### 5. 自动暂停与自动销毁

- **执行收尾**：默认执行后强制暂停。任务失败、超时或取消时也会尝试暂停；只有暂停已确认或沙箱已不存在，才释放运行名额。无法确认的沙箱保留记录，后台继续重试。
- **空闲暂停**：后台约每 5 秒检查一次。单独创建、恢复或选择保持运行的沙箱，默认空闲 30 秒后暂停；持有会话锁的执行任务不会被清理中断。
- **暂停销毁**：AstrBot 运行时后台约每分钟检查，暂停超过 `paused_sandbox_retention_hours` 的沙箱直接按 ID 销毁。默认 12 小时，普通聊天、查询状态和重复调用暂停不会延长保留时间。恢复或执行后再暂停，会重新计时。
- **状态持久化**：沙箱 ID、状态和暂停时间写入 `sandbox_sessions.json`，重启后继续清理。旧版记录没有暂停时间时使用最后一次沙箱活动时间。
- **失败重试**：销毁失败保留记录，后续检查重试；不会先恢复暂停沙箱，也不会把删除失败报告为成功。

自动销毁会永久删除云端沙箱里的变量和文件。超过保留时间后再执行，会创建新沙箱；需要长期保留状态时请调大保留小时数。AstrBot 停止运行时插件无法执行后台清理，重新启动后会继续处理到期记录。E2B 本身不会自动销毁已经暂停的沙箱。

## 文件传输与中文字体

- 附件 URL 及重定向目标只允许 HTTP/HTTPS。下载先检查 GET 响应的 `Content-Length`，再分块累计实际字节数；没有长度头的响应也受上传上限约束。下载失败或超限会明确报错并终止本次执行，避免模型使用不完整输入。网络操作设有超时，适配器自己的附件下载过程由适配器控制。
- 适配器返回的本地附件仍可读取，受同一上传上限约束；插件信任适配器提供的本地路径。HTTP/HTTPS 的限制不等同于内网访问隔离，现有本地 Bot 文件服务继续可用。
- 附件名中的目录部分会被去掉，文件统一写入 `/home/user/uploads/`。同名附件仍会覆盖该共享沙箱内的同名上传文件。
- 生成文件通过 E2B SDK `files.read(..., format="bytes")` 直接回读，保留 ZIP/Office 完整性校验，并检查实际大小是否与下载前一致；变化的文件会跳过，需待写入完成后重试。
- 中文绘图优先使用模板内的 `Noto Sans CJK SC`、`Noto Sans SC` 或 `WenQuanYi Zen Hei`。缺失时从 Noto 官方仓库下载固定的 Sans2.004 版本，校验大小、字体文件头、FreeType 解析和中文字形后原子写入缓存。坏缓存会删除重下，失败会输出警告并在下次执行重试，不再下载 SimHei。
- 推荐在自定义 E2B 模板中预装 `fonts-noto-cjk`（Debian/Ubuntu），然后填写 `default_template`，避免首次绘图依赖下载网络。Noto 字体遵循 [SIL Open Font License 1.1](https://github.com/notofonts/noto-cjk/blob/Sans2.004/LICENSE)，在模板中分发字体时保留随附许可。

## 🎮 使用示例

**1️⃣ 联网抓取**
* **用户**："看看 astrbot.app 首页的 title 是什么"
* **结果**：沙箱自带海外网络环境，自动联网抓取，LLM 根据返回结果直接告诉你网页标题。

**2️⃣ 绘图与文件分析**
* **用户**：(发了一个含有数据的 excel 文件) "帮我读取这个文件，并画一个饼图"
* **结果**：插件自动将你的文件塞进沙箱 -> 代码读取分析 -> 注入中文字体画图 -> 拦截图片并异步发回你的聊天窗口。

**3️⃣ 结果文件由模型自主发送**
* **用户**："把刚才那个表格里年龄大于 30 的人筛选出来，存成一个新的 excel 发给我。"
* **工作流**：
  1. 模型生成 `filtered_result.xlsx`
  2. 插件识别并缓存候选结果文件
  3. 模型调用 `e2b_sandbox_list_files` 查看候选列表
  4. 模型调用 `e2b_sandbox_send_file` 把真正想发的那个文件发给用户

## 💡 进阶：关于 E2B 模板 (Template) 的避坑指南

什么是模板？简单理解就是 E2B 里的 Docker 镜像。它可以让你提前装好笨重的依赖包，避免每次跑代码都要临时 `pip install`。

**怎么用最稳？**
1. **最省心的用法**：留空。如果你只是常规数据处理、画图、爬虫，直接用默认环境，什么都别管，最省事也最省钱。
2. **全局固定环境**：如果你自己（通过 E2B CLI/SDK）构建了一个包含了 `pandas`, `openpyxl`, `Pillow` 等常用库的模板，把它的 ID 填进配置里的 `default_template`，以后所有对话默认都从这个模板启动。
3. **按需指定环境**：如果你后面自己改成多工具版本，也可以额外扩展成“按次指定模板”的玩法；但当前 README 对应的默认版本里，主入口还是 `run_python_code` + `default_template`。

## 📝 注意事项与最佳实践

- **沙箱复用与资源释放**：当前会话的沙箱状态（变量、文件、依赖）会被保留，不再是每次清空的“一次性容器”。但请注意合理释放资源，任务结束后建议让模型暂停或销毁沙箱，避免长时间挂机空耗云端额度。
- **默认执行后自动暂停**：代码运行结束后默认强制暂停。需要短暂保持运行时，管理员需先开启 `allow_keep_running`，模型再传 `auto_pause=false`；沙箱仍会在空闲超时后暂停，不适合作为无限期后台服务。
- **结果文件按需精准发送**：沙箱生成的文件不会再被强制自动发到聊天中。它们会先存入本地缓存队列，由大模型根据你的要求，自主挑选并决定发送哪个最终结果给你，大大降低了错发率。
- **超大文件拦截保护**：为了防止撑爆宿主机的网络带宽和硬盘，超过设定体积上限的生成文件将被插件直接拦截并跳过。
- **图表绘制的稳妥写法**：当要求大模型进行数据可视化（画图）时，建议引导它使用“保存为图片文件”的方式（例如 `plt.savefig()`），而不是直接在代码中调用显示（`plt.show()`），以确保图片能顺利生成并回传。
- **屏蔽沙箱内部路径**：大模型有时会直接回复沙箱内的绝对物理路径（如 `/home/user/...`），这对本地聊天界面是无效的。建议提醒模型直接把处理好的文件发出来，而不是回复一条无法访问的路径。
