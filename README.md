# AstrBot E2B 云沙箱插件 (astrbot_plugin_e2b_sandbox)

![Platform](https://img.shields.io/badge/Platform-Windows%20%7C%20Linux%20%7C%20Docker-blue)
![License](https://img.shields.io/badge/License-AGPL--3.0-green)
![Python](https://img.shields.io/badge/Python-3.10+-blue)
![Status](https://img.shields.io/badge/Status-Active-brightgreen)

**使用 E2B 云沙箱安全执行 Python 代码，支持通过 LLM 自然语言调用。**

这是 AstrBot 的增强型代码执行工具，它将不安全的本地 Python 执行环境替换为隔离的云端沙箱。现在它不只是“能跑代码”，在文件处理、结果回传和自定义环境（Template）上已经有了一套非常顺滑的工作流。

## 💡 为什么用它？（核心优势）

- **💻 小鸡也能干大活**：代码计算、数据处理、画图全交给 E2B 云端服务器！哪怕你的 AstrBot 部署在 1核1G 的“乞丐版”小鸡上，也能把高负载计算丢给云端（宿主机只需留点内存和磁盘处理附件传输与缓存）。
- **⚙️ 极简配置，免折腾 Docker**：不用在宿主机折腾复杂的容器环境或排查依赖冲突。装好插件填个 API Key 就能让 Bot 跑代码干活，普通单 agent 开箱即用。
- **🛡️ 云端隔离，安全省心**：代码在独立云沙箱里执行，与 Bot 宿主环境彻底隔离。云端和本机各管各的权限，普通用户画图跑代码也不用要宿主机管理员。

## ⚠️ 重要前置要求（必读）

> [!IMPORTANT]
> 经实测，AstrBot 新版自带了“使用电脑能力”，用这个插件时，注意把本机和云端的配置分清：

### 🚫 不用为了 E2B 开启全局 Sandbox
在 AstrBot 的管理面板中，进入 **“设置” -> “普通配置” -> “使用电脑能力”**，找到 **“运行环境”** 选项：
- 请将它设置为 `local` 或者 `none`。
- **不用为了接入 E2B 把它改成 `sandbox`**，内置沙箱与这个插件不是一套驱动。
- 需要保留本机能力时选 `local`，并保留 `computer_use_require_admin=true`；只用 E2B 时也可以选 `none`。云端权限由插件自己的白名单控制。

### 🌐 网络环境配置
E2B 服务端在海外。如果你的 AstrBot 部署在国内且网络不通，请在插件配置中填写 `proxy`（例：`http://127.0.0.1:10809`）。

## 🛠️ 安装与配置

### 1. 安装依赖
```bash
# 进入 AstrBot 的虚拟环境后执行
pip install 'e2b-code-interpreter>=2.3.0,<3.0.0'
```

### 2. 获取 E2B API Key
访问 [E2B Dashboard](https://e2b.dev/) 获取 API Key，并填入插件配置。E2B 为独立云服务，使用可能产生费用；套餐、赠送额度、计费和服务端限制以 [官方定价](https://e2b.dev/pricing) 为准。

### 3. 插件配置项

**装好却叫不动？先看白名单！** 默认开启白名单，空名单会拒绝所有用户。填入允许的用户 ID，或关闭 `enable_user_whitelist`，再确认当前人格启用了 E2B 工具。升级后重载插件，用新对话试试。

配置面板使用短标题显示设置名称，补充说明放在 AstrBot 的 `hint` 区域（不同版本显示为说明文字或问号提示）。如果更新后仍显示旧标题，请重新加载插件、刷新管理面板并重新打开配置窗口。升级不会更改现有配置键或默认值。

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `e2b_api_key` | 字符串 | 是 | 空 | E2B API Key |
| `timeout` | 整数 | 否 | 60 | 单次代码执行超时（秒） |
| `max_output_length` | 整数 | 否 | 2000 | 返回给 LLM 的最大文本长度 |
| `proxy` | 字符串 | 否 | 空 | E2B 请求代理地址 |
| `default_template` | 字符串 | 否 | 空 | 默认使用的 E2B Template ID |
| `prefer_e2b_for_code` | 布尔值 | 否 | true | 本轮包含可用 E2B 执行工具时，注入日常代码优先走云端的提示 |
| `hide_restricted_local_tools` | 布尔值 | 否 | true | 用户通过插件准入、local 模式要求管理员时，为普通用户隐藏当前请求的本机 Shell、Python 和 Shell 会话工具 |
| `enable_user_whitelist` | 布尔值 | 否 | true | 是否限制为白名单用户；关闭后所有用户可用 |
| `user_whitelist` | 字符串列表 | 否 | 空 | 允许使用的用户 ID；启用白名单时留空会禁止所有用户 |
| `max_running_sandboxes` | 整数 | 否 | 3 | 本插件实例中所有会话合计的运行/待确认沙箱上限（1–20） |
| `max_queue_size` | 整数 | 否 | 10 | 满员时最多等待的请求数（0–100）；0 表示直接返回繁忙 |
| `queue_wait_timeout` | 整数 | 否 | 15 | 排队等待名额的最长秒数（1–120） |
| `allow_keep_running` | 布尔值 | 否 | false | 开启后才允许模型使用 `auto_pause=false`；空闲暂停仍生效 |
| `idle_pause_seconds` | 整数 | 否 | 30 | 没有执行任务的运行沙箱空闲多久后暂停（5–3600 秒） |
| `paused_sandbox_retention_hours` | 整数 | 否 | 12 | 暂停沙箱保留多久后自动销毁（1–720 小时） |
| `max_upload_file_size_mb` | 整数 | 否 | 20 | 上传到沙箱的单个附件上限（1–100 MB），同时限制 URL 下载和本地附件读取 |
| `max_return_file_size_mb` | 整数 | 否 | 5 | 允许缓存/发送的单个结果文件大小上限（MB） |
| `file_retention_hours` | 整数 | 否 | 24 | `data/plugin_data/astrbot_plugin_e2b_sandbox/exports/` 缓存文件保留时长（小时） |

### 4. 开放给所有用户

关闭 `enable_user_whitelist` 即可。建议先保留默认的 3 个运行名额、10 个排队请求和 15 秒等待超时；容量限制与白名单开关独立，关闭白名单不会关闭容量保护。

**群聊共享边界**：插件优先以 AstrBot 的 `unified_msg_origin` 作为会话标识。适配器以群标识会话时，同一群里的用户共用一个沙箱、Python 变量、上传附件和导出文件缓存；有调用权限的成员可以读取、发送或覆盖其他成员的文件，也可以暂停或销毁整个群的沙箱。白名单控制调用权限，不提供群内成员之间的数据隔离。当前版本继续保留这一共享模式，适合群内协作，请勿把它当作个人私密工作区。

暂停的沙箱可以保留各自的文件和变量，需要执行时再排队恢复。因此用户总数可以大于运行名额。创建、恢复和代码执行都使用同一套容量管理，正在运行的沙箱不会重复占用名额。新建请求按至少 1 秒间隔发送，`429` 按服务端 `Retry-After` 做有限重试；创建结果不确定时不会盲目再创建一个沙箱。

容量限制作用于单个插件实例，不是 E2B 项目的分布式配额管理。多个 AstrBot 实例或其他程序共享同一个 E2B 项目时，也会共享服务端额度，仍可能收到 `429`。建议为此插件使用独立项目，并留出并发余量；持续使用仍会消耗运行额度。

### 5. 自动暂停与自动销毁

- **执行收尾**：代码执行完毕默认强制暂停（任务失败、超时或取消也会尝试暂停），及时释放运行名额。若需短暂保持运行，需管理员开启 `allow_keep_running` 且模型传入 `auto_pause=false`，但仍受空闲超时限制。只有暂停已确认或沙箱已不存在才释放名额，未确认时后台继续重试。
- **空闲暂停**：后台约每 5 秒检查一次。单独创建、恢复或选择保持运行的沙箱，默认空闲 30 秒后暂停；持有会话锁的执行任务不会被中断。
- **暂停销毁**：后台约每分钟检查一次，暂停超过 `paused_sandbox_retention_hours`（默认 12 小时）的沙箱按 ID 直接销毁。普通聊天与查询不会重置计时，重新执行或恢复后再次暂停会重新计时。
- **状态持久化与重试**：沙箱 ID、状态与暂停时间保存在 `sandbox_sessions.json`，Bot 重启后继续清理；销毁失败保留记录后续重试。

> [!NOTE]
> 自动销毁会永久清空沙箱内的文件与变量。如需长期保留状态请调大保留小时数；Bot 停止期间后台清理暂停，重启后会补跑。

## 默认云端执行与本机权限

v1.3.3 默认开启 `prefer_e2b_for_code` 和 `hide_restricted_local_tools`。插件在 `on_llm_request` 中按请求复制工具集合，不修改 AstrBot 全局配置：

| 情况 | 行为 |
|---|---|
| 通过 E2B 准入，且本轮有 E2B 执行工具 | 提示计算、绘图、通用代码和附件处理直接使用 E2B，无需用户点名云沙箱 |
| 非管理员，`computer_use_runtime=local` 且 `computer_use_require_admin=true` | 在当前请求的工具集合副本中移除 `astrbot_execute_shell`、`astrbot_execute_python`、`astrbot_shell_session` |
| 管理员，或管理员要求已关闭 | 保留本机执行工具；普通代码仍可优先用 E2B |
| 使用内置 sandbox 或 none 模式 | 不按本机工具规则过滤，避免误删内置云沙箱工具 |
| E2B 工具未分配给主 agent、已禁用，或用户未通过插件准入 | 不宣告本轮可直接使用 E2B；不凭空添加工具或恢复被编排器移除的工具 |

- **不需要开启多 agent 编排**：普通单 agent 即可使用以上功能，不需要 router_system_prompt 或 sandbox_runner；即使没有启用 AstrBot 内置电脑能力，E2B 也按自身准入规则独立使用。若把 E2B 分配给某个子 agent，主 agent 就不会收到“直接调用 E2B”的提示，插件不覆盖这项编排决定；子 agent 的权限仍由 AstrBot 工具执行检查兜底。
- **环境必须区分**：E2B 的文件、进程、网络和软件包属于云沙箱；本机路径和 Skills 不会自动出现在云端。明确检查宿主机、Docker、AstrBot 服务或其他服务器时，仍使用目标机器的授权工具，缺少权限就说明原因；不能把云端执行结果当作目标机器结果。云端 Shell 任务可用 E2B Python 的 `subprocess` 执行，无需放开本机 Shell 权限。
- **本机文件、编辑、搜索和 Skills 工具保留**，由它们自身的权限和目录限制决定是否可用。关闭 `prefer_e2b_for_code` 只关闭本轮路由提示，E2B 工具本身的环境说明、生命周期和附件提示仍保留；默认云端是模型选择策略，不是把本机命令拦截后自动转发，工具隐藏也不替代原有权限校验。
- 接口与条件已核对 [AstrBot v4.28.1 的 ToolSet](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.1/astrbot/core/agent/tool.py) 和[本机权限检查](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.1/astrbot/core/tools/computer_tools/util.py)。升级后重载插件，并用新对话验证路由。

## 文件传输与中文字体

- **附件上传安全**：仅支持 HTTP/HTTPS 链接及适配器提供的本地附件，单个大小受 `max_upload_file_size_mb`（默认 20MB）限制，超限或下载失败直接终止执行。文件统一写入沙箱的 `/home/user/uploads/` 目录。
- **二进制安全回读**：生成文件通过 E2B SDK 以原始字节流下载，内置 ZIP / Office（.xlsx 等）文件完整性校验与体积核对，损坏或写入中的文件自动跳过，绝不发坏文件。
- **中文字体自愈**：画图优先使用沙箱内中文字体（Noto Sans CJK SC / WenQuanYi 等）；若缺失则自动从官方源下载固定版本的 Noto 字体并校验缓存后注入，彻底告别方块乱码。
- **模板预装建议**：自建 E2B 模板推荐预装 `fonts-noto-cjk`（遵循 [SIL Open Font License 1.1](https://github.com/notofonts/noto-cjk/blob/Sans2.004/LICENSE)），可免去首次画图下载字体的等待。

## 🎮 使用示例

**1️⃣ 联网抓取**
* **用户**："看看 astrbot.app 首页的 title 是什么"
* **结果**：沙箱自带海外网络环境，自动联网抓取，LLM 根据返回内容直接回答网页标题。

**2️⃣ 绘图与文件分析**
* **用户**：（发送 Excel 文件）"帮我读取这个文件，并画一个饼图"
* **结果**：插件自动将附件上传至沙箱 -> 代码读取分析 -> 注入中文字体画图 -> 生成图表并回传到聊天窗口。

**3️⃣ 结果文件由模型自主发送**
* **用户**："把刚才表格里年龄大于 30 的人筛选出来，存成新的 Excel 发给我"
* **工作流**：模型生成 `filtered_result.xlsx` -> 插件缓存候选文件 -> 模型调用 `e2b_sandbox_list_files` 查看列表 -> 模型调用 `e2b_sandbox_send_file` 精准把文件发给用户。

## 💡 进阶：关于 E2B 模板 (Template) 的避坑指南

什么是模板？简单理解就是 E2B 里的 Docker 镜像。它可以让你提前装好笨重的依赖包，避免每次跑代码都要临时 `pip install`。

**怎么用最稳？**
1. **最省心的用法**：留空。如果你只是常规数据处理、画图、爬虫，直接用默认环境，不用自己折腾模板。
2. **全局固定环境**：如果你自己（通过 E2B CLI/SDK）构建了一个包含了 `pandas`, `openpyxl`, `Pillow` 等常用库的模板，把它的 ID 填进配置里的 `default_template`，以后所有对话默认都从这个模板启动。
3. **按需指定环境**：创建和执行工具已经支持 `template` 参数，在新建沙箱时生效。想给现有会话换模板，先保存所需文件，再销毁旧沙箱、重新创建。

## 📝 注意事项与最佳实践

- **沙箱复用与资源释放**：当前会话的沙箱状态（变量、文件、依赖）会被保留，不再是每次清空的“一次性容器”。任务结束后建议让模型暂停或销毁沙箱，避免长时间挂机空耗云端额度。
- **执行后自动暂停**：代码运行结束后默认强制暂停以节省额度；需要保持运行时需管理员开启权限并由模型显式传参，详见 [5. 自动暂停与自动销毁](#5-自动暂停与自动销毁)。
- **结果文件按需精准发送**：生成的文件不会被强行全发到聊天中，而是先进入本地缓存，由大模型根据你的要求自主挑出结果文件发送，大大降低错发率。
- **超大文件拦截保护**：超过大小限制的生成文件会被插件直接拦截并跳过，防止撑爆宿主机的网络带宽和硬盘。
- **图表绘制稳妥写法**：做数据可视化画图时，建议引导大模型使用“保存为图片文件”（如 `plt.savefig()`）而不是直接在代码中 `plt.show()`，以确保图片顺利生成并回传。
- **屏蔽沙箱内部路径**：大模型有时会直接回复沙箱内的绝对物理路径（如 `/home/user/...`），这对本地聊天界面是无效的。建议提醒模型把文件发出来，而不是回复无法访问的路径。
