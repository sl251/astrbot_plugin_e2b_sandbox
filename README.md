**在聊天里完成计算、中文绘图和表格处理，并把结果文件发回给用户。**

模型通过插件在 E2B 云沙箱中执行 Python，处理上传的附件、生成图表和 Excel，并复用当前会话的文件与变量。普通单 agent 安装即可使用，多 agent 编排是可选项。通过插件准入的用户无需 AstrBot 管理员身份即可使用 E2B。

## 可以用它做什么

- **数据与文件处理**：读取 CSV/Excel，进行筛选、去重、日期统一、汇总和文件对比；具体处理步骤由模型编写代码完成。
- **中文绘图与交付**：生成带中文标注的图表，缓存生成文件，再由模型调用文件工具发送成品。
- **连续任务**：复用会话沙箱中的变量、文件和依赖，支持在上一次结果上继续修改。群聊默认共享同一会话沙箱。
- **控制云端资源**：运行容量上限、有界排队、默认执行后暂停、空闲暂停和到期清理共同管理沙箱生命周期。

任务代码在云端运行；AstrBot 宿主仍承担消息处理、附件传输、输出收集和导出缓存，会使用本地 CPU、内存、网络与磁盘。云端执行不授予用户宿主机权限。

## 安装后先做这几步

1. 确认 AstrBot **>=4.9.2**，安装插件依赖并填写 `e2b_api_key`。
2. **设置插件准入**：默认开启白名单且名单为空，此时所有用户都被拒绝。将允许的用户 ID 填入 `user_whitelist`，或关闭 `enable_user_whitelist` 向所有用户开放。
3. 在当前人格中启用 E2B 工具，保留 `prefer_e2b_for_code` 与 `hide_restricted_local_tools` 的默认开启状态。
4. 重载插件，用新对话直接要求生成一份图表或 Excel，确认附件实际交付。

从旧版升级无需重填原配置。新增上传上限默认 20 MB，可在 1–100 MB 范围调整；新启用的云端引导和本机工具隐藏也可分别关闭。群聊用户仍共享数据，请先阅读下文的共享边界。

## 执行环境与网络

E2B 插件独立于 AstrBot 内置电脑能力。普通安装可将 `computer_use_runtime` 设为 `none`；需要保留本机管理功能时使用 `local`，并保留 `computer_use_require_admin=true`。无需开启内置 `sandbox` 来接入 E2B，它们使用不同的驱动与配置。

云端的文件、进程和软件包不代表 AstrBot 宿主机或其他服务器的状态。明确针对宿主机的任务仍使用目标机器的授权工具，不会因缺少权限而静默转到 E2B。

宿主需要能连接 E2B 服务。网络不通时可填写插件 `proxy`，例如 `http://127.0.0.1:10809`。自定义模板预装中文字体可避免沙箱首次绘图依赖字体下载网络。

## 🛠️ 安装与配置

### 1. 安装依赖
```bash
# 进入 AstrBot 的虚拟环境后执行
pip install 'e2b-code-interpreter>=2.3.0,<3.0.0'
```

### 2. 获取 E2B API Key
访问 [E2B Dashboard](https://e2b.dev/) 获取 API Key，并填入插件配置。E2B 为独立云服务，使用可能产生费用；套餐、赠送额度、计费和服务端限制以 [官方定价](https://e2b.dev/pricing) 为准。

### 3. 插件配置项

配置面板使用短标题显示设置名称，补充说明放在 AstrBot 的 `hint` 区域（不同版本显示为说明文字或问号提示）。如果更新后仍显示旧标题，请重新加载插件、刷新管理面板并重新打开配置窗口。升级不会更改现有配置键或默认值。

| 配置项 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `e2b_api_key` | 字符串 | 是 | 空 | E2B API Key |
| `timeout` | 整数 | 否 | 60 | 单次代码执行超时（秒） |
| `max_output_length` | 整数 | 否 | 2000 | 返回给 LLM 的最大文本长度 |
| `proxy` | 字符串 | 否 | 空 | E2B 请求代理地址 |
| `default_template` | 字符串 | 否 | 空 | 默认使用的 E2B Template ID |
| `prefer_e2b_for_code` | 布尔值 | 否 | true | 本轮包含可用 E2B 执行工具时，注入日常代码优先走云端的提示 |
| `hide_restricted_local_tools` | 布尔值 | 否 | true | 用户通过插件准入、local 模式要求管理员时，为普通用户隐藏当前请求的本机 Shell、Python 和 Shell 会话工具 |
| `enable_user_whitelist` | 布尔值 | 否 | true | 是否限制为白名单用户；关闭后所有用户可用 |
| `user_whitelist` | 字符串列表 | 否 | 空 | 允许使用的用户 ID；启用白名单时留空会禁止所有用户 |
| `max_running_sandboxes` | 整数 | 否 | 3 | 本插件实例中所有会话合计的运行/待确认沙箱上限（1–20） |
| `max_queue_size` | 整数 | 否 | 10 | 满员时最多等待的请求数（0–100）；0 表示直接返回繁忙 |
| `queue_wait_timeout` | 整数 | 否 | 15 | 排队等待名额的最长秒数（1–120） |
| `allow_keep_running` | 布尔值 | 否 | false | 开启后才允许模型使用 `auto_pause=false`；空闲暂停仍生效 |
| `idle_pause_seconds` | 整数 | 否 | 30 | 没有执行任务的运行沙箱空闲多久后暂停（5–3600 秒） |
| `paused_sandbox_retention_hours` | 整数 | 否 | 12 | 暂停沙箱保留多久后自动销毁（1–720 小时） |
| `max_upload_file_size_mb` | 整数 | 否 | 20 | 上传到沙箱的单个附件上限（1–100 MB），同时限制 URL 下载和本地附件读取 |
| `max_return_file_size_mb` | 整数 | 否 | 5 | 允许缓存/发送的单个结果文件大小上限（MB） |
| `file_retention_hours` | 整数 | 否 | 24 | `data/plugin_data/astrbot_plugin_e2b_sandbox/exports/` 缓存文件保留时长（小时） |

### 4. 开放给所有用户

关闭 `enable_user_whitelist` 即可。建议先保留默认的 3 个运行名额、10 个排队请求和 15 秒等待超时；容量限制与白名单开关独立，关闭白名单不会关闭容量保护。

**群聊共享边界**：插件优先以 AstrBot 的 `unified_msg_origin` 作为会话标识。适配器以群标识会话时，同一群里的用户共用一个沙箱、Python 变量、上传附件和导出文件缓存；有调用权限的成员可以读取、发送或覆盖其他成员的文件，也可以暂停或销毁整个群的沙箱。白名单控制调用权限，不提供群内成员之间的数据隔离。当前版本继续保留这一共享模式，适合群内协作，请勿把它当作个人私密工作区。

暂停的沙箱可以保留各自的文件和变量，需要执行时再排队恢复。因此用户总数可以大于运行名额。创建、恢复和代码执行都使用同一套容量管理，正在运行的沙箱不会重复占用名额。新建请求按至少 1 秒间隔发送，`429` 按服务端 `Retry-After` 做有限重试；创建结果不确定时不会盲目再创建一个沙箱。

容量限制作用于单个插件实例，不是 E2B 项目的分布式配额管理。多个 AstrBot 实例或其他程序共享同一个 E2B 项目时，也会共享服务端额度，仍可能收到 `429`。建议为此插件使用独立项目，并留出并发余量；持续使用仍会消耗运行额度。

### 5. 自动暂停与自动销毁

- **执行收尾**：默认执行后强制暂停。任务失败、超时或取消时也会尝试暂停；只有暂停已确认或沙箱已不存在，才释放运行名额。无法确认的沙箱保留记录，后台继续重试。
- **空闲暂停**：后台约每 5 秒检查一次。单独创建、恢复或选择保持运行的沙箱，默认空闲 30 秒后暂停；持有会话锁的执行任务不会被清理中断。
- **暂停销毁**：AstrBot 运行时后台约每分钟检查，暂停超过 `paused_sandbox_retention_hours` 的沙箱直接按 ID 销毁。默认 12 小时，普通聊天、查询状态和重复调用暂停不会延长保留时间。恢复或执行后再暂停，会重新计时。
- **状态持久化**：沙箱 ID、状态和暂停时间写入 `sandbox_sessions.json`，重启后继续清理。旧版记录没有暂停时间时使用最后一次沙箱活动时间。
- **失败重试**：销毁失败保留记录，后续检查重试；不会先恢复暂停沙箱，也不会把删除失败报告为成功。

自动销毁会永久删除云端沙箱里的变量和文件。超过保留时间后再执行，会创建新沙箱；需要长期保留状态时请调大保留小时数。AstrBot 停止运行时插件无法执行后台清理，重新启动后会继续处理到期记录。E2B 本身不会自动销毁已经暂停的沙箱。

## 默认云端执行与本机权限

v1.3.3 默认开启 `prefer_e2b_for_code` 和 `hide_restricted_local_tools`。插件在 `on_llm_request` 中读取当前会话的 `provider_settings`，不会修改 AstrBot 全局配置：

**不需要开启多 agent 编排**。普通单 agent 安装可直接使用以上功能，不需要 router_system_prompt 或 sandbox_runner；即使没有启用 AstrBot 内置电脑能力，E2B 也可按自身准入规则独立使用。下述多 agent 说明仅适用于选择开启编排的用户。

| 情况 | 行为 |
|---|---|
| 通过 E2B 准入，且本轮有 E2B 执行工具 | 提示计算、绘图、通用代码和附件处理直接使用 E2B，无需用户点名云沙箱 |
| 非管理员，`computer_use_runtime=local` 且 `computer_use_require_admin=true` | 在当前请求的工具集合副本中移除 `astrbot_execute_shell`、`astrbot_execute_python`、`astrbot_shell_session` |
| 管理员，或管理员要求已关闭 | 保留本机执行工具；普通代码仍可优先用 E2B |
| 使用内置 sandbox 或 none 模式 | 不按本机工具规则过滤，避免误删内置云沙箱工具 |
| E2B 工具未分配给主 agent、已禁用，或用户未通过插件准入 | 不宣告本轮可直接使用 E2B；不凭空添加工具或恢复被编排器移除的工具 |

本机文件读写、编辑、搜索和 Skills 相关工具保留，由它们自身的权限和目录限制决定是否可用。工具集合的容器和列表按请求复制，不全局停用工具，也不改写其他用户或子 agent 的工具集合。关闭隐藏选项后，原本的管理员检查仍生效。

**环境必须区分**：E2B 的文件、进程、网络和软件包属于云沙箱；本机路径和 Skills 不会自动出现在云端。明确检查宿主机、Docker、AstrBot 服务或其他服务器时，仍使用目标机器的授权工具，缺少权限就说明原因；不能把云端执行结果当作目标机器结果。仅问“看看环境”而目标不明时，应先确认检查哪台机器。云端 Shell 任务可通过 E2B Python 的 `subprocess` 执行，无需放开本机 Shell 权限。

**可选的多 agent 编排**：日常任务可让主 agent 直接持有 E2B 工具，运维和仓库子 agent 继续负责各自目标。不需要专门添加 sandbox_runner。如果启用“移除主 agent 重复工具”并把 E2B 分配给某个子 agent，主 agent 就不会收到“直接调用 E2B”的提示；插件不覆盖这项编排决定。此请求钩子的过滤不能保证所有子 agent 也已过滤，子 agent 的权限仍由 AstrBot 工具执行检查兜底。插件没有读取或修改编排器配置，也不会创建任何子 agent。

保留 `computer_use_require_admin=true`，无需把内置运行环境切到 sandbox。关闭 `prefer_e2b_for_code` 只关闭本轮默认路由提示，E2B 工具本身的环境说明、生命周期和附件提示仍保留。默认云端是模型选择策略，不是把本机命令拦截后自动转发；工具隐藏也不替代原有权限校验。旧版/第三方宿主接口不兼容时会记录告警并保留原有工具权限机制。

接口与条件已核对 [AstrBot v4.28.1 的 ToolSet](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.1/astrbot/core/agent/tool.py) 和[本机权限检查](https://github.com/AstrBotDevs/AstrBot/blob/v4.28.1/astrbot/core/tools/computer_tools/util.py)。升级后重载插件，并用新对话验证路由，避免旧上下文中的权限报错影响模型选择。

## 文件传输与中文字体

- 附件 URL 及重定向目标只允许 HTTP/HTTPS。下载先检查 GET 响应的 `Content-Length`，再分块累计实际字节数；没有长度头的响应也受上传上限约束。下载失败或超限会明确报错并终止本次执行，避免模型使用不完整输入。网络操作设有超时，适配器自己的附件下载过程由适配器控制。
- 适配器返回的本地附件仍可读取，受同一上传上限约束；插件信任适配器提供的本地路径。HTTP/HTTPS 的限制不等同于内网访问隔离，现有本地 Bot 文件服务继续可用。
- 附件名中的目录部分会被去掉，文件统一写入 `/home/user/uploads/`。同名附件仍会覆盖该共享沙箱内的同名上传文件。
- 生成文件通过 E2B SDK `files.read(..., format="bytes")` 直接回读，保留 ZIP/Office 完整性校验，并检查实际大小是否与下载前一致；变化的文件会跳过，需待写入完成后重试。
- 中文绘图优先使用模板内的 `Noto Sans CJK SC`、`Noto Sans SC` 或 `WenQuanYi Zen Hei`。缺失时从 Noto 官方仓库下载固定的 Sans2.004 版本，校验大小、字体文件头、FreeType 解析和中文字形后原子写入缓存。坏缓存会删除重下，失败会输出警告并在下次执行重试，不再下载 SimHei。
- 推荐在自定义 E2B 模板中预装 `fonts-noto-cjk`（Debian/Ubuntu），然后填写 `default_template`，避免首次绘图依赖下载网络。Noto 字体遵循 [SIL Open Font License 1.1](https://github.com/notofonts/noto-cjk/blob/Sans2.004/LICENSE)，在模板中分发字体时保留随附许可。

## 使用示例与实测反馈

无需先说“使用 E2B”，直接描述任务和希望收到的文件。

### 中文收支图与 Excel

> 帮我画一张月度收支图：1—6 月收入分别是 8000、8500、7800、9200、9000、10500，支出分别是 6500、7000、8200、6800、7500、8000。用中文标注，展示每月结余，把图和数据 Excel 都发给我。

2026-10-08 的用户实测截图展示了中文标题、图例与负数结余，以及 `月度收支明细.xlsx`、`月度收支统计图.png` 两个附件卡片。

### 订单清洗与异常分离

> 生成一个客户订单测试表，包含重复订单号、空金额、不同格式的日期。然后按订单号去重、统一日期格式，把缺失金额的记录单独列出来。发我原始表、清洗结果和异常记录，并说明处理了多少条数据。

同日的用户实测截图展示了原始订单表、清洗结果表、异常记录表三个 Excel 附件及处理数量说明。也可以上传自己的表格，再明确匹配字段、去重规则和缺失值处理方式。

这些案例展示实际聊天中的绘图和附件交付；截图没有用于逐项核验 Excel 内部内容，也不能代表所有模型、消息平台和权限组合均已验收。

### 结果文件如何交付

模型生成文件 → 插件识别并下载候选文件到本地缓存 → 模型调用 `e2b_sandbox_list_files` 查看列表 → 调用 `e2b_sandbox_send_file` 发送选定文件。云端路径本身不是已交付附件；用户需要文件时，请在请求中说明“发给我”。

## 💡 进阶：关于 E2B 模板 (Template) 的避坑指南

什么是模板？简单理解就是 E2B 里的 Docker 镜像。它可以让你提前装好笨重的依赖包，避免每次跑代码都要临时 `pip install`。

**怎么用最稳？**
1. **最省心的用法**：留空。如果你只是常规数据处理、画图、爬虫，直接用默认环境，无需另外构建模板。
2. **全局固定环境**：如果你自己（通过 E2B CLI/SDK）构建了一个包含了 `pandas`, `openpyxl`, `Pillow` 等常用库的模板，把它的 ID 填进配置里的 `default_template`，以后所有对话默认都从这个模板启动。
3. **按需指定环境**：创建和执行工具支持 `template` 参数，仅在新建沙箱时选择模板。现有会话会复用旧沙箱；如需换模板，应先保存所需文件，再销毁旧沙箱并重新创建。

## 📝 注意事项与最佳实践

- **沙箱复用与资源释放**：当前会话的沙箱状态（变量、文件、依赖）会被保留，不再是每次清空的“一次性容器”。但请注意合理释放资源，任务结束后建议让模型暂停或销毁沙箱，避免长时间挂机空耗云端额度。
- **默认执行后自动暂停**：代码运行结束后默认强制暂停。需要短暂保持运行时，管理员需先开启 `allow_keep_running`，模型再传 `auto_pause=false`；沙箱仍会在空闲超时后暂停，不适合作为无限期后台服务。
- **结果文件按需精准发送**：沙箱生成的文件不会再被强制自动发到聊天中。它们会先存入本地缓存队列，由大模型根据你的要求，自主挑选并决定发送哪个最终结果给你，大大降低了错发率。
- **超大文件拦截保护**：为了防止撑爆宿主机的网络带宽和硬盘，超过设定体积上限的生成文件将被插件直接拦截并跳过。
- **图表绘制的稳妥写法**：当要求大模型进行数据可视化（画图）时，建议引导它使用“保存为图片文件”的方式（例如 `plt.savefig()`），而不是直接在代码中调用显示（`plt.show()`），以确保图片能顺利生成并回传。
- **屏蔽沙箱内部路径**：大模型有时会直接回复沙箱内的绝对物理路径（如 `/home/user/...`），这对本地聊天界面是无效的。建议提醒模型直接把处理好的文件发出来，而不是回复一条无法访问的路径。
